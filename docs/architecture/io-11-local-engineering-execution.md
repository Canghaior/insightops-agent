# IO-11 本地工程执行设计

## 目标和使用路径

在 InsightOps 的「报告 → 单项任务」打开一个已经冻结且就绪的任务，选择本机登记的 Git 仓库和提交、模型、写入范围并补充指令。启动后，InsightOps 自行阅读源码、给出计划、在独立副本修改和创建文件、运行 Maven 验证，保存实际执行过程。使用者可刷新或重新登录查看进度、差异、原始构建输出与结果交接包。

首版支持单模块 Maven、Java 21 测试环境、UTF-8 文本源码与单项变更。任务入口绑定准确的报告、工程基线和任务版本。仓库的已提交树是源码起点，服务核对工程基线 POM 和随原件导入的源码文件。已有工作区的未提交内容始终由维护者持有。线上发布、远程工作区、通用 Shell、自动提交与 PR 属于后续独立范围。

## 组件和信任边界

| 组件 | 职责 |
| --- | --- |
| Vue 单项任务面板 | 取能力和已登记仓库、选模型和起点、录入指令及相对写入范围，发起或取消本地执行，回读状态、工具记录、构建事实和产物。保留已有外部执行包及手工回接入口。 |
| 本地执行服务 | 在本机运行的 InsightOps Java 进程中按配置启用。验证账户、报告、任务、基线和目录登记，保存状态并调度有限任务。常规环境默认关闭这个入口。 |
| 现有模型网关 | 选用同一个 `AgentPlanningModelGateway`，由既有路由调用 OpenAI 或 DeepSeek。工程任务单独提供结构化工具，复用模型选项、用量和费用估算。 |
| 本机执行器 | 从指定提交创建独立 Git 副本，运行受控的文件查询和文本变更。将用于构建的源码复制到每次构建独有的目录。只有该目录和单独制备的 Maven 依赖缓存挂入一次性容器。 |
| PostgreSQL 与交付服务 | 保存运行与工具记录，复用构建导入、逐项 Surefire 对照、任务结果及交接包。完整的分步 Maven 证据和模型交换也能按运行下载。 |

本机登记目录由运行配置指定，页面只传登记键和已展示的提交号。本机入口对工作区 Owner 或系统管理员开放，并同时校验报告与任务的访问权。运行产物目录与登记目录分开。Git 操作不使用模型提供的命令或绝对路径。构建镜像、Maven 参数和挂载点由服务配置与代码固定。构建容器使用本机已存在的镜像与依赖缓存，工作目录只含该次构建的源码快照。禁止挂载原仓库、Git 元数据、应用数据、Docker socket 和供应商凭据，默认断开构建网络。需要额外 Maven 依赖时提前向独立缓存补齐。模型接收所选指令、冻结任务和完成步骤所需的文件片段，仓库内容和命令输出作为观察材料传递。

## 执行与状态

1. **受理。** 服务端校验任务属于可用报告、就绪且引用工程基线。冻结仓库键、完整提交号、POM SHA-256、任务版本、指令、模型和写入范围。请求 UUID 与启动参数绑定，相同参数重放返回同一次运行。单个本机实例同一时间运行一项工程任务。
2. **准备和基线构建。** 按认证工作区核对登记仓库，在独立 Git 副本中核对原件及提交树中的 `pom.xml`。先按冻结的 Maven 方案运行原始源码，验证镜像、依赖及实际执行范围。保留时间、镜像、退出码、日志和可取得的 Surefire XML。依赖缺失、零项实际执行和超时在首次模型调用前收口。
3. **只读分析。** 模型使用文件工具定位相关代码和原测试，再提交计划。页面展示文件和实际工具事件。
4. **试改与测试。** 执行阶段开放相同的读工具、受控写入与测试。每次写入检查准确的旧文件哈希或新增要求，随后把执行结果还给模型。每次候选测试关联当时的实际补丁哈希。允许根据失败输出修改后重试，保留各次结果。预算由模型轮次、工具数、用量、可取得的费用估算和构建超时限制。
5. **归档。** 使用执行器生成实际 Git diff（含新增文件）。产品按 XML 和退出码观察结果。候选当前补丁与最近构建必须对应，通过条件包括实际有测试通过、退出码为 0、无 failure/error，原先执行的测试身份未消失或由通过变成跳过。保留失败和跳过，允许有明确原件支持的失败执行形成结果。可以回传同一任务的原始补丁、基线和候选证据，产品不代替维护者记录合并决定。

最终候选若新增 Java 测试源文件，执行器从原提交建立第三个副本，仅复制该次新增的 `src/test/` 内容，在相同参数和隔离环境完成对照。以 suite、class、name 匹配测试。只有唯一配对、可归属到新测试源文件的旧断言失败与新通过计入区分数。重复身份、错误、跳过、编译失败、缺少原件、镜像差异分别限制解释。归档中另存这轮原件及结构化归纳，历史行和导出的旧记录保留原样。

执行状态包括 `QUEUED`、`BASELINE`、`ANALYZING`、`EDITING` 和 `TESTING`。最终区分 `SUCCEEDED`、`FAILED`、`BLOCKED`、`CANCELLED` 和 `INTERRUPTED`。状态和事件保存在 PostgreSQL。取消时工作线程结束当前构建；进程重启后中断任务可回读，再次运行产生新 ID。

## 工具契约

| 工具 | 输入和执行 |
| --- | --- |
| `list_files` | 接收相对目录、可选路径子串和页码。返回路径和下一页。 |
| `search_code` | 接收相对目录、文字及页码，返回路径、行号、片段和下一页。 |
| `read_file` | 接收相对路径与行号范围，返回 UTF-8 文本片段和原文件 SHA-256。 |
| `write_file` | 接收相对路径、期望旧 SHA-256（新建时为空字符串）、完整的新文本。只允许冻结的文件或源目录，原子写入目标。已有测试文件保留，新增用例写入独立测试文件。 |
| `write_files` | 一次提交 1 至 8 项文件变更。预检所有路径、权限和旧哈希，写入发生 I/O 错误时回退该组已写文件。 |
| `run_maven_tests` | 使用受理时冻结的默认测试或指定测试类方案验证当前差异。返回实际命令、状态、计数和日志片段。 |

文件访问验证规范路径、授权范围、链接和体积。只读阶段工具表没有写入或构建动作。各阶段通过网关通用工具调用交换数据，模型关于执行成功的陈述不能改变实际退出码或测试统计。生产的补丁以执行器持有的工作副本对照原始 Git 快照生成。

## 接口与交付物

在 `/api/v1/reports/{reportId}/tasks/versions/{taskVersionId}/local-execution` 提供能力、仓库、模型和运行列表。其下的 `/runs` 发起新运行，`/runs/{runId}` 读取详情，`/runs/{runId}/cancel` 请求停止，`/runs/{runId}/evidence.zip` 下载运行原件。访问检查沿用当前报告和任务所属的账户与工作区，证据请求同样从该上下文定位。

一次正式运行保存请求模型、实际返回的模型、每轮工具调用与结果、用量、工作区和提交、POM 指纹、任务和基线 ID、构建命令环境、时间和退出码、原始日志、Surefire XML 及实际补丁。运行原件 ZIP 中每个内容条目列出字节数和 SHA-256。产品原有结果交接包使用正式导入的基线与最终候选证据，执行中间记录由本地运行原件包提供。两个导出都能由任务页面打开。外部执行、人工验证和历史报告仍使用既有接口。

## 实施顺序与验收

1. 后端实现本机登记、提交及 POM 核验、文件工具与独立构建环境，先跑路径、哈希冲突和新文件 diff 测试。
2. 接入双模型工具调用、数据库记录和现有结果回接，测试鉴权、重放、取消、失败、证据一致及 V51 数据迁移保护。
3. 加入任务页面与本机启动说明，跑前后端回归和一次实际认证态闭环。
4. 用 IO-09 金额规则样例的独立 Git 快照验收。指令是拒绝零金额，保留负数拒绝及正数两位舍入，创建独立回归测试类。由 InsightOps 实际读、建文件、改实现、跑两侧 Maven、保存并导包。另行核对新测试在旧实现上失败，结果包的源码起点、补丁和测试原件能独立复核。默认真实模型为 GPT-6.2 Astra，另检查 DeepSeek 工具协议。模型实际不可用时如实记录对应环节，不用固定回答替代产品验收。
5. 完成浏览器刷新、重新登录、进程重启及旧记录重下载核对。交付本机地址、使用入口、实际版本、模型、构建证据和范围。保留原 IO-08 至 IO-10 证据和原数据库。
