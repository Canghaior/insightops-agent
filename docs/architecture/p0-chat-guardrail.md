# P0 聊天 Guardrail

> 状态：已实现并纳入发布门禁
>
> 范围：Alpha/P0 的研究问答入口、上下文和 GitHub Release 证据

## 1. 目标

P0 Guardrail 只解决当前真实链路中的最小安全边界：阻止异常输入进入运行链路，把用户消息、历史消息和工具内容明确标记为不可信数据，并保证实时版本结论只能引用三个白名单项目的 GitHub 官方 Release 页面。

它不是完整的内容审核系统，也不承诺抵御所有模型层面的提示注入。登录、租户隔离、账号级权限、通用网页内容净化和人工审批属于 P1 以后范围。

## 2. 输入门禁

- 去除首尾空白后再处理，空输入直接返回 HTTP 400。
- 最大长度为 4000 个字符，前后端使用相同限制。
- 拒绝除换行、回车和制表符以外的 ISO 控制字符。
- 历史消息和当前消息放入显式的 `untrusted` 边界，不把其中的命令当作系统指令。
- 系统策略禁止用户消息改变项目白名单、工具范围或安全规则，也禁止泄露系统提示词、API Key、Authorization 和 Cookie。

## 3. 工具与输出门禁

- GitHub Release 工具继续使用项目侧固定白名单，模型不能自由指定仓库。
- 工具返回的引用必须符合 `https://github.com/{owner}/{repo}/releases/tag/{tag}`；其他来源在模型调用前失败，错误码为 `OUTPUT_SOURCE_NOT_ALLOWED`。
- 没有工具证据时，模型不得编造实时版本、发布日期或来源链接。
- 前端只按安全 Markdown 子集渲染回答，过滤原始 HTML、脚本链接和危险协议。
- 所有成功、失败和拦截结果继续写入 Agent Run，便于在执行记录中审计。

## 4. 自动化验收

发布门禁至少覆盖：

1. 正常输入规范化。
2. 空输入、超长输入和控制字符拒绝。
3. 提示注入文本保持在不可信边界内。
4. 系统策略包含工具白名单和敏感信息保护要求。
5. 只接受 GitHub 官方 Release tag URL。
6. 非法引用在调用模型之前终止并记录失败。
7. 危险 Markdown/HTML 不在浏览器执行。

对应测试位于 `P0ChatGuardrailTest`、`ChatStreamControllerTest` 和前端 Markdown 渲染测试。

## 5. P1 延伸项

- 登录用户、工作区和会话授权。
- 针对外部网页、文档和 RAG 内容的统一净化与来源策略。
- 可配置的敏感信息检测、内容分类和审计告警。
- 高风险工具的审批、幂等、速率限制和细粒度权限。
