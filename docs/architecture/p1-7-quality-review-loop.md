# P1.7-A 反馈复核与评测回流

## 目标

P1.7-A 把 P1.6 的答案/引用反馈从“只入库”升级为受管理员审核、可进入回归评测且受发布门禁保护的质量闭环：

```text
用户答案反馈 / 引用纠错
  -> 管理员查看用户、会话、Run、模型、答案和官方引用
  -> 已处理 / 忽略 / 转为评测候选
  -> 候选题编辑与双阶段批准
  -> 从已批准候选构建不可变草稿版本
  -> 基础 50 题 + 反馈候选运行完整 RAG 评测
  -> PASSED 后才允许激活
  -> 后续默认发布门禁自动使用激活版本
```

## 数据模型

- `research_answer_feedback`、`research_citation_feedback` 增加复核人、复核说明和复核时间。
- `rag_evaluation_candidate` 保存来自单条反馈的结构化案例，状态为 `DRAFT / APPROVED / REJECTED / INCLUDED`。
- `rag_dataset_version` 保存 Workspace 级版本、基础数据集、候选数量、门禁 Run 和激活审计。
- `rag_dataset_version_case` 在创建版本时复制候选内容，使版本不受后续草稿编辑影响。
- 每个 Workspace 同时最多只有一个 `ACTIVE` 版本，由数据库部分唯一索引保证。

## 权限与隔离

- 所有 `/api/v1/admin/quality/**` 接口只允许 `SYSTEM_ADMIN`。
- 所有反馈、候选、版本和评测 Run 查询均强制带 `workspace_id`。
- 普通用户只能通过原反馈 API 修改自己的 Run 反馈；重新提交会回到 `PENDING` 并清空旧复核结论。
- 管理员不能修改原始 Run、答案和引用，只能记录复核结论和创建评测候选。

## 发布门禁

- 草稿版本由固定 `p1-rag-questions-v3-50` 与该版本候选题组合运行。
- 版本评测以版本名写入 `rag_evaluation_run.dataset_name`，完整保存每题与聚合指标。
- 激活事务只接受该 Workspace 与该版本名的最新一次 Run，且其状态必须为 `PASSED`；没有评测或最新评测失败时均返回冲突并拒绝激活。
- 激活新版本时旧 `ACTIVE` 版本自动进入 `RETIRED`。
- 常规“一键运行评测”会自动加载当前 `ACTIVE` 版本；没有激活版本时继续使用固定 50 题基础集。

## 当前边界

- 本阶段不自动把所有负面反馈加入评测集，避免噪声和恶意内容污染发布门禁。
- 候选题的预期项目、必命中词、答案应包含词和来源域名必须由管理员确认。
- P1.7-A 不包含专用 Reranker、自动修复知识库、报告导出或站外通知。
