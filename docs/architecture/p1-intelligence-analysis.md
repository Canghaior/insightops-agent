# P1.3 技术情报分析、摘要与站内通知

## 目标

把 P1.2 保存的 GitHub Release 从“更新列表”升级为面向 Java 开发者、架构师和技术负责人的结构化情报：说明主要变化、Java 影响、升级价值、风险和建议动作，并保留官方证据、模型用量和成本审计。

## 分析链路

1. P1.2 采集器写入一条新 Release 时，将该事件标记为 `analysis_eligible=true`。
2. V11 上线前已有的事件保持 `false`，不会自动消耗模型额度；系统管理员可在更新中心逐条手动请求分析。
3. Worker 使用数据库锁领取任务；同一事件在一个工作区内只生成一条分析，避免并发重复调用。
4. Release 标题、摘要和 URL 被包在 `<UNTRUSTED_RELEASE_DATA>` 中。系统提示明确禁止服从 Release 内的指令、泄露密钥、调用工具或声称访问了其他网页。
5. DeepSeek 只能返回固定 JSON 结构。服务端校验枚举、必填文本、数组数量、长度和证据 URL；非结构化输出直接失败，不会作为有效情报展示。
6. 成功结果写入 `intelligence_analysis`，同时记录 Provider、模型、Token、估算人民币成本和价格生效日。
7. 关注该项目的用户收到站内通知；高风险分析另发高优先级通知。

## 默认成本与重试边界

- 每个工作区每天最多自动/手动执行 5 次模型分析。
- 每次最多输出 1600 Token。
- 临时失败最多重试 2 次，总尝试次数最多 3 次，使用退避时间重新排队。
- 非法结构化输出不重试，直接进入终止失败，避免重复消耗额度。
- 摘要由已保存的结构化分析确定性聚合，不再调用模型。

以上限制可通过 `.env` 中的 `INTELLIGENCE_ANALYSIS_*` 配置调整。普通自动化测试全部使用假模型，不访问 DeepSeek。

## 摘要与通知

- 用户可在设置页选择 `OFF`、`DAILY` 或 `WEEKLY`，设置时区、投递小时和项目范围。
- 每日摘要覆盖用户本地时区的前一天；每周摘要在星期一生成，覆盖上一自然周。
- 摘要和通知仅站内展示，不发送邮件、微信或 Webhook。
- 分析、摘要、通知查询都经过当前账户、工作区和个人关注关系过滤。

## 权限

- 所有登录用户：查看自己关注项目的情报，配置自己的摘要，读取自己的通知。
- `SYSTEM_ADMIN`：查看工作区分析队列、今日调用量、估算成本和失败状态，并可为历史 Release 手动请求分析。
- 普通用户调用管理员分析接口返回 `403`；重复请求成功中、运行中或已完成的任务返回 `409`。

## 当前边界

- 证据仅限已登记项目的官方 GitHub Release URL。
- 不自动访问 Issue、PR、Roadmap、博客或任意网页。
- V11 之前已有的 79 条 Release 默认不自动分析。
- 真实 DeepSeek 验收必须由项目负责人明确确认后单独执行。
