# P2.4 Agent 工作流表达与模板

## 1. P2.4-A 范围

P2.4-A 提供 Workspace 级可复用工作流模板、不可变版本、活动版本原子切换、激活审计和运行前可视化预检。它解决“把常见研究方法保存下来并在执行前看懂任务图”的问题，不改变 P2.1 已有的 Agent 运行时安全边界。

本阶段内置四类模板：

- 版本对比。
- 框架选型。
- 升级影响评估。
- 技术专题研究。

模板可将入口研究问题带入研究问答，但 P2.4-A 不强制现有聊天 Run 按模板图执行。模板图直接绑定运行、依赖输出表达式和失败节点定点重跑属于 P2.4-B。

## 2. 持久化模型

Flyway V35 增加：

- `agent_workflow_template`：Workspace、名称、分类、状态和当前活动版本。
- `agent_workflow_template_version`：不可变版本、入口问题和 JSONB 图规范。
- `agent_workflow_activation_audit`：记录前后版本、操作者、原因和时间。

同一 Workspace 内模板名称唯一；版本号在模板内单调递增。激活新版本时，旧活动版本在同一事务内变为 `RETIRED`，模板只指向一个活动版本。

## 3. 图规范与预检

图规范复用 P2.1-B 的条件 DAG 合同：节点 ID、工具、参数、依赖、条件和 required 标志。保存和激活前必须通过：

1. 节点数量、ID 唯一性、依赖存在性和无环校验。
2. 工具已注册且已启用。
3. 参数符合工具输入 JSON Schema。
4. 写工具不能与其他节点并行。
5. 写工具即使进入模板，真实执行时仍必须走现有人工审批。

预检只返回规范化图、分层波次、最大并行度、写节点数量和警告，不创建 Agent Run、不预留成本、不执行工具。

## 4. 管理 API 与页面

Owner 和系统管理员可使用 `/api/v1/admin/agent-workflows`：

- 读取模板、版本和可用工具合同。
- 预检图规范。
- 创建模板 v1。
- 为已有模板创建不可变新版本。
- 激活已复核版本并写入审计。

前端 `/admin/agent-workflows` 提供模板库、结构化节点编辑、依赖/条件编辑、分层 DAG 预览、版本选择、激活和入口问题带入研究问答。
