# P2.4-B 模板驱动 Agent Run

## 1. 范围

P2.4-B 让 P2.4-A 的活动模板版本直接创建真实、可恢复的 Agent Run，增加受限输入/输出表达式、节点级持久状态和失败节点定点重跑，同时保持 P2.0 至 P2.3 已建立的审批、幂等、补偿、预算、租约和成本边界。

## 2. 模板快照与幂等启动

普通成员通过 `/api/v1/agent-workflows` 读取当前 Workspace 的活动模板，并在 `/agent-workflows` 提交入口参数。启动请求必须携带预期活动版本 ID 和幂等 request ID；若管理员在提交前切换活动版本，服务返回冲突，客户端必须刷新后重试。

创建 Run 时在同一事务中：

1. 创建普通 `agent_run`。
2. 将 `templateId`、`templateVersionId`、模板名称/版本、入口问题、规范化入口参数、完整 `graphSpec` 和工具合同指纹写入不可变运行快照。
3. 为每个逻辑节点创建运行态记录。
4. 通过 P2.3-B 的持久工作队列入队；浏览器仅观察 Run，不持有执行生命周期。

因此模板后续新建版本、活动版本切换甚至模板删除，都不会改变已经创建的 Run。

## 3. 受限输入/输出表达式

图规范新增根级 `inputs` 和节点级 `exposeOutputs`。支持两类表达式：

- `${inputs.topic}`：读取已声明且通过类型、长度和范围校验的入口参数。
- `${research.output.sources}`：仅读取显式依赖节点在 `exposeOutputs` 中允许公开的字段。

表达式可作为完整 JSON 值保留数组、对象、数字和布尔类型，也可嵌入字符串；对象或数组不能嵌入普通字符串。保存/激活时验证引用来源、显式依赖和输出白名单，启动时验证入口参数，节点调度前解析并再次通过工具输入合同。未知参数、缺失值、类型不匹配、未声明依赖或未公开字段均在工具调用前失败。

工具合同指纹固化工具名、版本、输入/输出 Schema、风险和审批策略。运行恢复前若当前合同与快照不一致，Run 以 `WORKFLOW_TOOL_CONTRACT_CHANGED` 安全失败，不使用漂移后的合同静默执行。

## 4. 持久执行与节点恢复

Flyway V36 增加：

- `agent_workflow_run`：一对一绑定 `agent_run` 的模板、版本、图、输入和工具合同快照，以及重试血缘。
- `agent_workflow_run_node`：逻辑节点、依赖、参数模板、公开字段、状态、解析后输入、输出、Token、费用、错误和重用来源。
- `agent_workflow_node_attempt`：节点尝试次数、Run attempt、Worker、lease token、输入输出、费用、错误和耗时。

固定 DAG 复用 P2.1 的分层图、预算、写工具独占与审批边界，复用 P2.3-B/C 的持久队列、心跳租约、fencing token、事件日志、超时结算和成本单次结算。每个完成波次写安全点；实例接管时从节点表恢复已成功输出，成功节点不再执行，旧 lease 不能提交节点结果。旧实例遗留的运行中尝试标记为 `FAILED / RUN_RECOVERED`，新实例以递增 attempt 继续。

失败 Run 可指定一个真实失败逻辑节点创建新 Run。新 Run 固化原 Run 的同一模板版本、图和输入快照；此前所有成功节点复制为 `REUSED` 并保留来源节点 ID、输出、证据和费用，失败及未完成节点重新执行，不重复调用已经成功的工具。

写工具仍由 Registry 风险、人工审批、Effect 幂等和补偿状态机治理。固定 DAG 遇到 `WAITING_APPROVAL` 后在当前波次安全结束，不会把待审批写操作描述为已完成，也不会提前执行下游；取消节点立即按 Run 取消语义结算。

## 5. API 与前端闭环

成员 API：

- `GET /api/v1/agent-workflows`：读取活动版本及入口参数定义。
- `POST /api/v1/agent-workflows/{templateId}/runs`：按预期活动版本创建快照并入队。
- `GET /api/v1/agent-workflows/runs/{runId}`：读取本人 Run 的模板快照、节点和尝试。
- `POST /api/v1/agent-workflows/runs/{runId}/retries`：从真实失败节点创建带血缘的新 Run。

前端 `/agent-workflows` 提供活动模板选择、动态入口表单和启动入口；`/runs/{runId}` 在现有执行时间线之上展示模板版本、合同指纹、真实节点状态、尝试次数、耗时、Token、费用、解析输入、原始输出、下游可见输出、失败原因、Tool Call 跳转、最新安全点和失败节点重试。运行中详情每两秒静默刷新，页面刷新不会影响后台执行。

## 6. 安全不变量

- 运行只接受当前活动版本，且客户端必须提供预期版本防止 TOCTOU。
- Run 使用创建时快照，不在执行时回读活动模板。
- 节点写入先验证当前 Run lease；旧 Worker 不能写节点、尝试或终态。
- 下游只能读取显式依赖且显式公开的输出字段。
- 重试只复用来源 Run 的成功节点，并以新 Run 保存完整血缘。
- 节点状态、尝试与普通 Tool Call/Plan 节点互相链接，审批、幂等、补偿、预算和成本结算边界不变。
