# P2.4-C 工作流产品化

## 1. 范围

P2.4-C 在 P2.4-A 模板治理和 P2.4-B 持久执行之上补齐四项产品能力：

- 可拖拽 DAG 画布与可视依赖编辑。
- 绑定不可变活动版本的用户运行参数预设。
- 可移植模板包及有期限、可撤销的跨 Workspace 分享。
- 基于真实工作流 Run、节点、反馈、引用、Token、费用和耗时的模板质量趋势。

P2.4-C 不改变执行器。节点布局只用于编辑和回放；工具权限、写操作审批、幂等 Effect、失败补偿、租约 fencing、安全点、预算预留和单次结算继续由 P2.0-D、P2.1 和 P2.4-B 控制。

## 2. 可视化 DAG

管理端画布使用节点卡片和 SVG 依赖边表达模板图，支持拖动节点、增加依赖和移除依赖。坐标以节点 `position: {x, y}` 元数据写入图规范，并随不可变模板版本持久化。

坐标不参与 DAG 语义，也不进入节点输入。服务端仍先将完整 JSON 规范化，再执行节点、依赖、循环、工具合同、表达式和并行写节点门禁；规范化过程保留未知展示元数据。旧版本没有坐标时，前端按节点序号生成确定性网格位置，避免新版本保存后节点全部重叠。

## 3. 参数预设

Flyway V37 增加 `agent_workflow_parameter_preset`。预设同时绑定：

- Workspace。
- 所有者用户。
- 模板。
- 不可变模板版本。
- 预设名称和已规范化参数 JSON。

读取、保存和删除都带 Workspace 与用户条件。保存前复用 P2.4-B 输入解析器完成未知字段、必填值和类型校验；只允许为当前活动版本保存或读取。活动版本切换后，旧预设不会被错误应用到新合同，用户需要为新版本创建新预设。

## 4. 导入、导出与分享

模板包采用 `schemaVersion = 1`，只包含模板元数据、来源版本号、入口问题和图规范，不包含数据库 ID、活动状态、Run、用户数据、审批、费用或分享令牌。

导入始终创建新的草稿模板和 v1，不继承来源 ID 或活动状态，并经过现有模板创建边界重新校验图、表达式和工具合同。导入后仍需 Owner 预检和显式激活。

分享使用 256 bit 随机令牌。数据库只保存 SHA-256 哈希，不保存原始令牌；原始令牌只在创建响应中返回一次。分享期限为 1 至 90 天，可由来源 Workspace Owner 撤销，并记录导入次数和最近导入时间。

浏览器分享链接把令牌放在 URL fragment 中，fragment 不随页面 HTTP 请求发送；预览和导入 API 只接受 POST body，避免令牌出现在查询串、API 路径和常规访问日志中。共享预览和导入仍要求已认证的 Owner 或系统管理员；过期、撤销或未知令牌统一失败。

## 5. 模板质量趋势

质量趋势按 Workspace 和模板隔离，最多读取指定窗口内最近 5,000 个真实工作流 Run。指标源为：

- `agent_workflow_run`：模板和不可变版本快照。
- `agent_run`：终态、耗时、Token 和最终费用。
- `agent_workflow_run_node`：节点数与 `SUCCEEDED/REUSED` 数。
- `research_answer_feedback`：回答反馈。
- `research_citation_feedback`：引用反馈。

反馈先按 Run 聚合，再与 Run 和节点指标连接，避免多个 Workspace 成员反馈同一 Run 时重复计算 Run 数、Token、费用或节点数。服务端输出总览、UTC 日趋势、版本对比和最近运行；没有反馈或引用时比率为 0，但页面显示为无数据。

该查询是只读视图，不建立第二套成本账本。费用只读取 `agent_run.estimated_cost_cny` 的最终值，继续以现有成本预留和 SETTLE/RELEASE 流水为唯一结算事实。

## 6. API 与权限

普通已认证成员可管理自己的 `/api/v1/agent-workflow-presets`。模板分析、导入导出和分享位于 `/api/v1/admin/agent-workflow-products`，仅 Workspace Owner 或系统管理员可用。

所有模板读取和撤销操作都从当前账户取得 Workspace，不接受客户端提供 Workspace ID。共享令牌只用于定位被分享的不可变版本，不能提升工具、模板管理或 Workspace 权限。

## 7. 恢复与兼容边界

模板分享或活动版本切换不会改变已创建 Run。P2.4-B 在 Run 创建时固化的 `template_id`、`template_version_id`、入口问题、图、输入和工具合同指纹仍是执行和恢复的唯一依据。

成功节点复用、失败节点定点重跑、跨实例租约接管和安全点恢复都忽略展示坐标。导入模板中的写工具也不会绕过审批、幂等与补偿边界。
