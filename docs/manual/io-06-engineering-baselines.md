用户可直接选一个单模块根 POM。它可以保留自定义的 `.xml` 文件名，产品按 Maven POM 内容校验，原始名称和字节随版本保存。手头是普通源码 ZIP 时，可以解压后选择该模块的根 POM。需要导入多份工程材料时，在授权源码副本外执行 `python scripts/maven_baseline_pack.py --project <单模块根> --scope <范围.json> --output <新包.zip>`。它复用只读提取器。已有 `manifest.json` 可通过 `--legacy-manifest` 原样带入，需与输入源码字节及只读重算的结果相符。支持可选的 `--dependency-tree`、`--maven-version`、`--application-log`。这些参数指向已有记录，打包与产品均不运行 Maven 或项目代码。

包内 baseline.json 列出格式、调用方基线标签、关注坐标和每件原件的 SHA-256；sources/ 保留白名单工程相对路径；evidence/ 保存提取结果及选定的既有记录。格式、数量、大小、目录、重复路径和哈希在服务端核对。提取器旧版完整清单可供下载。产品的事实快照仅包括本版能核对的种类，不能将上传者的任意 JSON 作为产品已核验的工程事实。

案例使用已审 Petclinic 固定源码与 Spring 官方 REST 指南的独立 complete 模块。分别记录 Maven 声明、静态属性展开、外部 Maven 解析记录、构建工具 JDK、应用进程 JDK、用户说明与未知项。业务档案和工程原件分开保存。单次评估只接收明确选择的基线中的结构化事实与来源，没有自动采集或嵌入工程原件。

## 如何阅读一个版本

本地选模块时，在系统档案打开「导入工程资料」，选择「选择本机模块目录」。目录清单先由浏览器读取。选定包含业务代码的 Maven 模块后，根 POM 自动纳入。可按需勾选 Java 实现、测试、包装器配置、应用配置与已有的依赖树、Maven 版本或启动日志。选择「生成工程包并预览」会提交列出的文件，服务端校验单模块范围，并按 v1 格式保留文件、长度与 SHA-256。可以下载这份 ZIP，或继续保存此次预览为新版本。已有 Surefire XML 会单独列出，可在报告的构建对照中导入。目录打包不会启动工程。只有脱离浏览器使用旧命令行提取器时才需要准备 scope JSON。

| 页面上的内容 | 核对办法 |
| --- | --- |
| POM 声明 | 打开指定路径和行号。依赖声明没有写版本时，实际版本保持未知，或另列提供的 Maven 解析结果。 |
| 静态推导 | 展开当前 POM 中可以确定的属性，同时记录使用位置和定义位置。外部父 POM、活动 Profile 及跨继承属性缺少材料时记录原因。 |
| Maven 解析、构建工具环境、应用进程观察 | 分别对应所给依赖树、Maven 版本输出及受支持的启动日志。每条绑定文件与行号。执行时间、源码来源或部署环境的对应关系需要另外取证。 |
| 档案原文、导入者说明、待核对差异 | 预览保存导入时的档案修订及技术栈。明确的 Java、Spring Boot 值可触发核对提醒。维护者仍需判断两处记录指的是构建目标、父 POM 还是运行进程。 |
| 原件 | 在系统详情展开已存版本，下载完整原件或包内单件。哈希核对字节是否一致，来源提交由提供者另行核对。 |

在系统详情导入并预览后，保存会核对当前档案修订、输入字节以及预览指纹。同一提交重试返回已存版本；改变输入需重新预览。选定基线的评估以该版本为准。再次研究沿用上次选择，可以显式更换版本或选「不关联工程基线」。已经归档的验证交接从原报告取得当时的工程基线，验证的实验环境与构建引用保存在其具体记录版本。
