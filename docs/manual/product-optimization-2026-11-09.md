# 产品优化与验收（2026-11-09）

本轮按“可信评估 → 减少使用成本 → 真实用户验证”推进。代码改动不代表生产已部署，也不代表真实用户试用已完成。

## 第一批：一次研究可追溯、可交付

- 更新中心的 Release 可直接发起升级评估，服务端按工作区、用户关注状态和登记仓库解析 `eventId`，再次提交时重新校验。
- 框架、目标版本与原始事件一并带入；业务预设仍保留用户当前版本、环境、资料。一次性触发事件不污染可复用业务预设。
- 非 Release 进入事件研究问答，来源上下文与可编辑的补充问题分开；切换会话使未完成的事件加载失效。
- 执行状态与资料完整性分开。工具失败、缺少结果、版本范围/引用缺口、其他维护分支或较晚版本资料会显式提示。
- “可进入人工核查”仅说明自动完整性检查未发现已知结构缺口，不能解释为结论已验证或兼容性保证。
- 聊天回答可直接保存报告、下载 Markdown/PDF、打开研究详情。新消息保存准确 Run 关联；V42 仅为唯一精确匹配的旧消息回填关联，歧义记录保留空值。
- 新报告固化资料完整性检查、输入、触发事件与证据快照。历史报告不重新计算、不改写；重复保存保持原有幂等行为。
- Java/Vue 固定证据样例覆盖限流、版本缺口、跨分支、较晚版本资料和引用编号问题。最终事实正确性仍需独立的答案回归、语义评测与人工校准。
- RAG 生成样本实际检查 `answerMustInclude` 并参与门禁，V43 保存逐题检查结果；管理页展示缺少内容与引用问题。另有 Java/Vue 合成证据的 2 个正例与 8 个最终答案反例，支持读入已生成答案进行离线回归，见 [最终答案回归说明](../evals/final-answer-regression.md)。这些规则不宣称语义验证通过。

## 第二批：降低理解与重复操作成本

- 常用导航收敛为工作台、我的项目、更新与提醒、研究、报告。相关页面进入二级导航；账号、工作区与管理诊断保留在可展开分组。
- 聊天显示资料收集/版本核对等阶段，任务图、用量和 TraceId 折叠，失败与待确认提示仍在默认视图可见。
- 升级表单展示来源状态、采集时间、文档/片段数量、同步提醒以及资料处理状态；不把采集成功称为目标版本覆盖已核验。
- 系统状态明确区分模型配置与实际验证；关键词检索降级、未确认的采集/投递状态如实展示。接口不产生付费模型探测。
- 两条聊天执行路径共用来源分类校验和相同的基础系统提示。此次仅收敛这些公共规则，整个旧执行路径仍保留兼容。
- 新公开工作区默认每日 10 万 Token / 2 元、每月 100 万 Token / 20 元，环境变量可配置，单并发与硬限额保留。已有工作区不被自动改写；这不等于平台总预算已实现。

## 第三批：真实试用准备与判定

`/getting-started` 提供完整使用指南和可选试用记录：开始/结束计时、独立完成情况、来源核对、报告采用情况、原方式耗时和困难说明。记录只保留在本页内存，下载后由参与者主动分享，不自动上传，不填写密钥或项目机密。

请邀请 3～5 位目标用户，至少覆盖一位 Java 开发者、一位前端开发者及一位技术负责人。每人使用真实任务，先记下惯用工具与资料渠道；不要用开发者代演结果替代用户反馈。

| 任务 | 观察内容 | 本轮建议验收目标 |
|---|---|---|
| 第一次升级评估 | 是否理解项目、版本、背景与资料缺口 | 无口头指导能发起研究，并解释证据状态 |
| 从版本提醒进入评估 | 是否需要重填框架、目标版本、业务背景 | 事件准确，已有业务配置可复用 |
| 核对两条关键结论 | 项目、版本、原文是否支持结论 | 能找到原文，并识别尚未验证的兼容性 |
| 保存与重新打开报告 | 下载、刷新、历史报告与来源 | 输入和证据一致，旧报告未被覆盖 |
| 同一项目第二次研究 | 重填次数、时间与新增资料缺口 | 主要修改目标版本和变化的背景 |

对照任务使用相同问题、相近难度及相同证据截止时间，交替安排 InsightOps 与惯用方式的先后顺序，避免把学习效应当节省时间。记录实际用时、补充操作次数、是否得到帮助、报告采用原因；失败任务同样保留。小样本用于发现问题，不据此宣称总体效率提升百分比。

两周后询问是否自主再次使用、实际采用了哪份报告、为何未再次使用。根据反馈决定团队共享配置、报告复核和两次研究差异功能的优先级；本轮不宣称这些扩展已实现。

## 验证与部署边界

本轮已执行：

| 检查 | 结果与边界 |
|---|---|
| 前端测试 | 33 个文件、94 项通过，包含真实 ChatView 的事件异步隔离、上下文保留及刷新入口消费回归 |
| 前端 Lint / 生产构建 | 通过 |
| 后端离线 `mvn verify` | 382 项中 381 通过、1 项按条件跳过；被跳过的是需要另行提供实际回答文件的可选评测入口 |
| 数据库门禁 | 在一次性 pgvector/PostgreSQL 容器与随机隔离 schema 中执行，包括 V41→V42 唯一/歧义历史回填、V43 结果往返、事件权限、报告快照和工作区隔离 |
| 浏览器界面 | 使用真实前端构建和明确标注的只读样例检查桌面及 390px 窄屏；确认事件目标版本、业务配置复用、来源提示及聊天补充问题。仅验证界面，未将样例当作真实研究 |

测试未读取真实模型密钥或发起付费研究。隔离数据库与界面样例服务验证结束后关闭。

部署前应用全部 Flyway 迁移，并核对当前部署实际启用的检索、采集与交付能力。升级后抽查一条旧会话、新事件研究、资料缺口报告与真实下载。生产登录、付费模型研究、外部投递及真实用户效果均需单独验收。
