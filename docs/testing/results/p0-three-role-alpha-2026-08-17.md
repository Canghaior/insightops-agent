# P0 三角色 Alpha 验收结果

> 日期：2026-08-17
>
> 环境：本地真实 PostgreSQL、真实 DeepSeek、真实 GitHub Release API、真实浏览器页面

## 结论

Java 开发者、架构师和技术负责人三个目标角色的内部工作流模拟均通过，共完成 9 个用户任务。验收中发现的外部链接信任边界和多轮时间窗口丢失问题已修复并复测，不保留为 P0 已知失败。

| 角色 | 任务数 | 结果 | 核心证据 |
|---|---:|---|---|
| Java 开发者 | 2 | PASS | 最新版本、上一版本变化、多轮指代 |
| 架构师 | 3 | PASS | 90 天跨项目比较、同口径追问、事实/推断分离 |
| 技术负责人 | 4 | PASS | 试用基线、风险清单、行动建议、提示注入拒绝 |

## 共同问题与产品判断

1. Release 数据足以完成版本初筛和变化摘要，但不足以独立完成最终技术选型；兼容矩阵、文档、Issue/PR、性能与生产案例需要 P1 数据源或人工核验。
2. 两项目 90 天对比可能返回 20 条以上证据，回答偏长；P1 应增加摘要层级、折叠和结构化对比视图。
3. P0 仅保存当前标签页会话并支持最近 100 条回看；登录、会话列表、跨设备同步和可管理长期记忆仍按计划进入 P1。
4. Release 正文属于不可信外部内容。P0 已去除其中外部链接目标，前端只把经过验证的 GitHub Release tag URL 渲染为可点击证据。

## 修复回归

- 提示注入内容保持在不可信消息边界内。
- 非白名单仓库不会进入工具路由。
- 追问可同时继承白名单项目和显式时间窗口。
- 每项目证据条数由服务端给出，模型无需自行统计。
- 可点击证据限定为 HTTPS GitHub Release tag URL。
- 技术负责人会话刷新后恢复 `USER/ASSISTANT` 共 8 条消息。
